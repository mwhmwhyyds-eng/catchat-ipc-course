# 实现说明

本文件解释程序代码，不是课程实验报告。实际测试记录与界面采集保存在单独的 evidence 目录中。

## 数据通路

```text
Windows SSH 终端一                         Windows SSH 终端二
         │                                         │
         ▼                                         ▼
    鲁班猫进程 A  ─── msgsnd ──▶ [B 接收队列] ── msgrcv ──▶ 进程 B
         ▲                                         │
         └────── msgrcv ── [A 接收队列] ◀── msgsnd ──┘
```

每个房间用 `msgget(IPC_PRIVATE, 0600)` 创建两个队列。`IPC_PRIVATE` 在这里表示每次创建新队列，访问权限仍由 mode 控制。A、B 在受锁保护的本房间状态文件中取得相同的队列 ID；每个进程只消费自己的接收队列，避免读走自己刚发出的消息。

通过角色锁排除同房间重复角色。任意一端可先启动，先启动者创建会话，另一端复用。不同房间拥有独立状态目录与队列。

## 同时输入与接收

单进程事件循环负责接收、键盘输入、界面刷新。`msgrcv(..., IPC_NOWAIT | MSG_NOERROR)` 非阻塞读取，单轮最多处理 32 个包；随后 `poll()` 等待标准输入，超时最多 50 ms。System V 队列 ID 不是可直接交给 poll 的文件描述符，因此队列按有界周期检查。

该设计不需要多线程共享 UI，也不因键盘输入阻塞接收。空闲时会等待，不采用无延迟的忙循环。50 ms 是轮询间隔设计值，不是已经测得的端到端延迟保证。对端状态每约 200 ms 检查一次，状态栏约每秒更新。

发送使用 `IPC_NOWAIT`。内核队列满时返回 `EAGAIN`，程序提示且保留草稿，不阻塞整个 UI。

## 消息结构

`ChatMessage` 首成员为正数 `long mtype=1`，之后为协议标记、文本长度、会话随机标识、发送端实例、接收端实例、序号、时间、昵称和正文。传入 `msgsnd/msgrcv` 的大小不含首成员 `mtype`。正文按实际 UTF-8 字节数发送，避免每条短消息都占用整个最大缓冲区。

每个端点重新启动时生成新的实例标识。接收方验证会话、接收实例、长度、字符串终止符及 UTF-8 可显示性；旧实例遗留包与无效包计入丢弃计数。该协议用于同机同构进程，未定义跨主机字节序和 ABI，也不提供密码学认证。

## 会话生命周期与其他项目隔离

`control.lock` 串行化加入、离开、状态文件操作和角色探测；`A.lock/B.lock` 上的 `flock` 在进程生命周期内保持。进程崩溃后内核自动释放文件锁，避免仅依赖 PID 复用敏感的存活检查。后台角色探测使用非阻塞锁；发送时最多等待约 50 ms 以跨过正常的短暂竞争；启动、检查和关闭最多等待约 1 s。即使另一进程暂停在持锁位置，输入事件循环也不会无限阻塞。

最后一个在线端点正常退出时，以 `msgctl(IPC_RMID)` 删除本房间队列。两端强杀后，再次加入同房间会验证并回收旧队列，建立新会话。显式 `--cleanup` 在端点在线时失败。

队列身份检查包括 ID、记录时的 `msg_ctime`、创建者与所有者 UID、0600 权限以及私有 key；不扫描或删除其他程序的队列。先核对两个队列，再执行删除；身份检查或删除失败时保留状态文件，防止丢失后续检查所需的引用。`msg_ctime` 也会随 IPC_SET 变化，若人为修改权限/容量，程序会保守停止自动回收。状态文件解析失败时不会覆盖原记录建立新会话。角色锁文件不 unlink，避免并发进程分别锁住不同 inode。锁用于本项目进程协作，同一系统用户仍可用系统调用干预自己的队列。

异常边界：`SIGKILL`/断电不能执行用户态清理。若进程恰在队列创建后、状态记录写入前被强杀，可能留下尚未记录的队列；程序不会为清理这种极小窗口而冒险删除其他项目资源。日常故障恢复测试覆盖的是端点启动完成后的强杀。

## 终端处理

以 termios 切换原始输入，使用 ANSI alternate screen、256 色、光标定位及 bracketed paste。退出路径恢复 termios、光标与屏幕。信号处理器只设置 `sig_atomic_t` 标记，清理在主循环返回后执行，不在信号处理器里调用 stdio 或复杂 IPC 操作。

使用 `mbrtowc` 与 `wcwidth` 计算终端列宽。编辑按 Unicode 码点边界处理，不把 UTF-8 多字节汉字删成半个。该编辑器不是完整的 Unicode grapheme cluster 编辑器；复杂 emoji、组合字符呈现仍受终端影响。

正文拒绝 ESC 等控制字符，防止把收到的文字当作终端控制序列。长消息按显示列换行，尽量保留 ASCII 单词/数字；超长单词仍折行。输入行水平滚动，全屏重绘时恢复草稿光标。浏览历史时根据新消息实际占用行数调整滚动偏移，并显示新到消息数量，Ctrl+G 返回底部。可视行索引按需扩容，避免大量长消息时固定索引截掉最新消息。历史最多 300 条。导出文件名增加递增序号，使用 `O_EXCL`、`O_NOFOLLOW` 与 0600，连续导出也不会覆盖已有文件。

仅含空白的昵称与消息会被拒绝。板端精简 C.UTF-8 的字符分类实测未把 U+3000 识别为空白，因此依据 Unicode 15.1 `White_Space` 属性补齐判断，不完全依赖 `iswspace()`。

## 验证范围

`make check` 使用真实 Linux 子进程与内核队列验证中文双向收发、并发顺序、房间隔离、重复角色、离线草稿、重新加入、背压重试、旧实例包拒绝、两端强杀后恢复及正常清理。

PTY 测试覆盖中文编辑、拆分到达的 UTF-8、输入期间接收、多行粘贴、窗口缩放、1024 字节边界、记录导出、信号退出及 termios 恢复。另注入无效超大包和仅删除专用测试队列，检查错误路径。

测试不能替代对字体、配色、行宽和长文字布局的人工视觉检查。`tests/capture_demo.py` 记录实际板端 PTY 字节流（`.ansi`）及 asciicast v2 记录（`.cast`），用于终端重放和界面检查。对其渲染得到的图片应注明来源，不能声称是 Windows 桌面的原生截屏。
